About

A tactical Tetris running on my own C++ engine, SimpleEngine2D. Instead of guiding falling blocks, you drag pieces from a deck of three and place them on the board.

Engine philosophy

Manual Memory (RAII) No garbage collector. Deterministic resource lifecycles using Smart Pointers and Value Semantics.
Cache Locality Data-oriented design. Contiguous memory allocation using std::array for the game board.
ECS Architecture Strict separation of data (Components) and logic (Systems) for an extensible foundation.
Decoupled Systems Type-safe EventBus architecture to broadcast line clears and state changes across the engine.

Introduction

I started this project to build a fast game engine, SimpleEngine2D, in modern C++ without giving up memory safety. Tetris is the game running on it. There's no Garbage Collector: I manage resource lifecycles entirely through RAII (Resource Acquisition Is Initialization).

Without a commercial engine's "magic", I can see what actually happens in memory. The project combines modern C++17 features with Data-Oriented Design.

Reimagining Tetris with C++

Building the SimpleEngine2D foundation, RAII memory management, and moving from real-time to tactical drag-and-drop gameplay.

1. Design: drag-and-drop mechanic

In classic Tetris, pieces fall while you guide them. Here you drag 3 different pieces from the bottom bar and place them on the board, closer to a mathematical deck management game. That moves the genre from "real-time reflex" to "tactical placement."

2. Memory management and object lifecycle

Modern C++ is strict about object ownership. Here is how I handled it:

  • Value semantics: I defined Tetromino pieces as structs and kept them on the stack, instead of treating everything as a "reference" like in C#.
  • Smart pointers: Core engine systems live in std::unique_ptr, so each has one owner and its memory is released when the engine shuts down.
  • Decoupling: A type-safe EventBus tells the engine when a piece is dropped or a line is cleared.

3. Technical architecture: ECS

SimpleEngine2D is built on an Entity-Component-System (ECS) architecture. A Tetris block is just an Entity (an ID). Its position lives in a TransformComponent and its visual in a SpriteComponent.

Engineering insight

Why std::array over std::vector for the board? The 10x18 grid never changes size, so std::array keeps it in one contiguous block with no separate heap allocation, which is good for CPU cache locality.

4. Modern C++ touches

C++17's std::optional and std::variant improved my error handling. To check whether the mouse is holding a piece, I use std::optional<Piece> instead of a raw null pointer, which is cleaner and safer.
